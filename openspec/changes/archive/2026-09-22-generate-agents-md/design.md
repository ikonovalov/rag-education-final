# Design: Создание AGENTS.md для репозитория master

## Overview
Изменение чисто документационное: создаётся один новый Markdown-файл
`master/AGENTS.md`, наполнение которого выводится из анализа фактического
состояния репозитория (exploration-notes.md), а не из шаблонного
`structure.txt` или README. Код, зависимости и конфигурация не меняются.

## Decisions

### Decision: Единственный источник инструкций — AGENTS.md
**Выбор:** Создать только `AGENTS.md`, не создавать параллельно `CLAUDE.md`,
`QWEN.md`, `GIGACODE.md`.
**Обоснование:** Запрос пользователя касался только `AGENTS.md`; остальные
файлы правил на момент изменения отсутствуют, поэтому конфликтов приоритета
между ними нет — расширение скоупа не требуется.
**Альтернативы:** Создать также CLAUDE.md/QWEN.md/GIGACODE.md как копии —
отклонено как выходящее за рамки запроса.

### Decision: Наполнение по факту кода, а не по README/structure.txt
**Выбор:** Раздел "Структура репозитория" в `AGENTS.md` строится по
фактическому листингу `src/`, `scripts/` и точек входа, а не по
`structure.txt` (устарел) или README (частично совпадает, но не описывает
реальные модули `src/`).
**Обоснование:** `structure.txt` описывает шаблонную структуру
(`retriever.py`, `rag_pipeline.py`, `tests/`), которая не соответствует
реальному составу репозитория — использование его как источника ввело бы
агентов в заблуждение.
**Альтернативы:** Актуализировать `structure.txt` вместо/вместе с созданием
`AGENTS.md` — отклонено, так как явно вне скоупа запроса (см.
exploration-notes.md, раздел "Открытые вопросы").

### Decision: Явные предупреждения вместо исправления несоответствий
**Выбор:** Нерабочий импорт `src.rag_pipeline` в `main_workflow.py` и пустой
`config/config.yaml` фиксируются в `AGENTS.md` как предупреждения ("известно,
но не исправлено"), без изменения самого кода.
**Обоснование:** Задача — документационная; исправление обнаруженных багов
требует отдельного изменения с собственным review/тестированием.
**Альтернативы:** Исправить импорт в рамках этого изменения — отклонено, так
как это выходит за рамки "сгенерировать AGENTS.md" и меняет поведение кода.

## Architecture
Не применимо — изменение не затрагивает архитектуру системы, только
документацию для агентов.

## Data Model
Не применимо.

## Implementation Notes
- Файл `AGENTS.md` — обычный Markdown, без специального парсинга или
  инструментов генерации.
- Разделы файла (минимально необходимые, согласно delta-spec
  `agent-instructions`):
  1. Обзор проекта.
  2. Актуальная структура репозитория (точки входа, `src/*`, `scripts/*`).
  3. Установка и запуск (`pip install -r requirements.txt`,
     `cd scripts && python download.py && python build_index.py`,
     `streamlit run main_agent.py` / `streamlit run main_workflow.py`).
  4. Переменные окружения (имена из `.env-example`, без значений секретов).
  5. Известные несоответствия и риски (нерабочий импорт в
     `main_workflow.py`, пустой `config/config.yaml`, устаревший
     `structure.txt`).
  6. Явное указание на отсутствие `tests/`, CI и линтер-конфигов.
- Реальные значения из `.env-example` (ключи, токены) в `AGENTS.md` не
  копируются — только имена переменных.

## Risks
- Риск устаревания: при будущей реструктуризации `src/` содержимое
  `AGENTS.md` может разойтись с кодом. Митигация — вне скоупа текущего
  изменения; будущее изменение должно обновить файл отдельно.
- Риск неполноты: явных конвенций code style в репозитории не обнаружено —
  раздел "стиль кода" в `AGENTS.md` не включается, чтобы не декларировать
  непроверяемые правила.
